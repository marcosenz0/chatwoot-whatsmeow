## Compatibility decisions

- Preserved the WhatsMeow channel, status synchronization, QR pairing, inbox settings, group tabs and actions, group membership, stickers, reactions, edits, deletes, replies, contacts, media and multi-inbox behavior.
- Preserved conversation pipelines, message selection/forwarding, MarcosX IA routes and branding, and the custom OpenAI/Groq audio transcription and summary integration.
- Incorporated the upstream Chatwoot voice-call UI and APIs without treating `Channel::Whatsmeow` as an official WhatsApp Cloud Calling inbox.
- Kept the upstream Vite configuration split (`vite.config.ts`, `vite.lib.config.ts`, `vite.shared.ts`, and `vitest.config.ts`).
- Merged upstream translation keys with the fork-specific catalogs instead of replacing either side.
- Kept the custom group-aware conversation counts. The upstream optimized three-count query cannot represent the fourth group count or the hidden-group tab rules.
- Integrated the 55 fork commits that were published after the original upgrade baseline, including status, identity reconciliation, session recovery and WhatsApp Cloud Studio changes.
- Replaced the removed status-viewer `EmojiInput` import with the current shared `EmojiPicker` contract; this was required for the production bundle to compile on Chatwoot 4.16.2.

## Pre-deployment backup

Do not run the new migrations against production until both persistent stores have been backed up:

1. Create a PostgreSQL dump of the Chatwoot database and verify the dump can be listed/restored.
2. Back up the WhatsMeow session/store database used by `whatsmeow-service`.
3. Record the currently deployed Chatwoot and WhatsMeow image digests.
4. Keep the old images available until QR/session recovery, messaging and media smoke tests pass.

The code upgrade has not been deployed and no staging or production database migration has been executed as part of this work.

## Deployment smoke tests

1. Run pending Rails migrations in the Linux release environment.
2. Verify Chatwoot boots and workers start without migration or autoload errors.
3. Verify the existing WhatsMeow session reconnects without a new QR code.
4. Send and receive direct text, image, document, voice note and sticker messages.
5. Verify reactions, replies, edits and delete-for-everyone.
6. Verify group listing, group conversations, membership actions and CSV export.
7. Verify two inboxes sharing a phone number still receive the expected events.
8. Verify status badges, QR pairing, auto-read, always-online, ignore options and call rejection settings.
9. Verify pipelines, message selection/forwarding, MarcosX IA and audio transcription/summary.
10. Verify the Calls navigation does not expose WhatsApp Cloud Calling controls for a WhatsMeow inbox.

## Rollback

For a code-only rollback, redeploy the images built from the backup tag or backup branch. If the upgraded release ran Rails or WhatsMeow store migrations and the old binaries cannot read the upgraded schemas, restore both database backups together with the old images. Do not roll back only one service when the failure involves their shared message/session contract.
