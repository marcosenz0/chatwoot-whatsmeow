## Compatibility decisions

- Preserved the WhatsMeow channel, status synchronization, QR pairing, inbox settings, group tabs and actions, group membership, stickers, reactions, edits, deletes, replies, contacts, media and multi-inbox behavior.
- Preserved conversation pipelines, message selection/forwarding, MarcosX IA routes and branding, and the custom OpenAI/Groq audio transcription and summary integration.
- Incorporated the upstream Chatwoot voice-call UI and APIs without treating `Channel::Whatsmeow` as an official WhatsApp Cloud Calling inbox.
- Kept the upstream Vite configuration split (`vite.config.ts`, `vite.lib.config.ts`, `vite.shared.ts`, and `vitest.config.ts`).
- Merged upstream translation keys with the fork-specific catalogs instead of replacing either side.
- Kept the custom group-aware conversation counts. The upstream optimized three-count query cannot represent the fourth group count or the hidden-group tab rules.
- Integrated the 55 fork commits that were published after the original upgrade baseline, including status, identity reconciliation, session recovery and WhatsApp Cloud Studio changes.
- Replaced the removed status-viewer `EmojiInput` import with the current shared `EmojiPicker` contract; this was required for the production bundle to compile on Chatwoot 4.16.2.

## Rollback

For a code-only rollback, redeploy Chatwoot from `backup-origin-develop-pre-chatwoot-4.16.2-20260801` and WhatsMeow from `backup-whatsmeow-staging-pre-upgrade-20260801`. If the old binaries cannot read the migrated schema, restore the verified dump together with both old services. Do not roll back only one service when the failure involves their shared message/session contract.
