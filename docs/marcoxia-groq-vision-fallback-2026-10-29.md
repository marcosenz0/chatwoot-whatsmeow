# MarcoXIA: Groq, independent vision and fallback connections

The release supports `qwen/qwen3.8-27b` as the preferred Groq chat and vision model, with `openai/gpt-oss-120b` retained for chat comparison. Vision settings in Identity and model select the provider/model independently, image size, video frame count/interval and description instructions. Video analysis is sampled; the frame count respects the smallest image cap among compatible primary/reserve models. Qwen accepts three images per request. Text in attachments remains untrusted data.

Voice and audio is the second agent section. Incoming transcription has independent primary/reserve settings and supports OpenAI, Groq and Gemini. Outgoing MiniMax/ElevenLabs synthesis and manual audio review are unchanged: preparing opens text by default, explicit synthesis creates the preview, and sending preserves that exact recording and idempotency without activating paused AI.

## Named connections and routing

Each account can save several named API connections for each provider. Chat, vision and transcription each select a primary connection and an optional reserve with its own provider, connection ID and model. A reserve may use another account with the same provider. Referenced IDs are scoped to the Chatwoot account and provider; the exact same connection cannot be both primary and reserve. New named accounts require their own supplied key. Keys remain encrypted where application encryption is configured and are never included in API responses, health records or prompts.

Legacy connections are preserved. An enabled Groq/OpenAI audio integration may provide the default connection virtually when no usable explicit credential exists; an explicitly disabled default is respected. Virtual credentials must not be appended to an autosave association. Migration `20261029200000` adds names and health/status JSON columns and replaces the provider-only uniqueness index with account/provider/name. Do not reverse it by deleting additional accounts or keys.

Provider authentication, balance, rate, server, timeout/network and empty-response failures can trigger the reserve during generation. A business/configuration failure does not trigger another provider. When a reserve exists, Groq skips its bounded short rate-limit waits and immediately tries the reserve. Otherwise the prior bounded `Retry-After` behavior remains. Output budgets are independently configurable for chat and vision primary/reserve. Groq defaults to768 rather than4096 because a real HOT1 request was rejected for estimated output1361 against the account free quota1000/minute. OpenAI8000 and Gemini8192 defaults are preserved. Token-limited incomplete responses are rejected before parsing/delivery and can use the reserve; billed OpenAI usage is recorded before that fallback. Simultaneous calls still share the provider quota. A response that succeeded is returned even if monitoring persistence fails; the caller must not repeat a billed generation or send because status logging failed.

The separate **Try the primary on each new execution** switch defaults to ON. A failed generation is completed using the reserve with the same input; the next execution starts on the primary again. With the switch OFF, the successful reserve remains first across requests, elapsed time and key repairs until it fails or the operator changes/inverts the route. A reserve failure still tries the primary. The **Swap primary and reserve** button exchanges provider, model, connection and output budget within the selected service; Save applies the edit. It preserves instructions, activation and other services. Inherited image/transcription choices are resolved into explicit compatible routes when inverted. There are no paid periodic health probes. The dashboard polls redacted status, shows a red failed connection and green exact connection in use, and keeps key drafts intact during polling. Saving a repaired key clears that connection's failure; Test connection validates the selected connection without hiding its failure behind a reserve.

Two copies of the same API key may share the same balance and limits; they do not create independent quota. Gemini has automated mocked coverage only because no live Gemini key was provided. If both accounts fail, the operation reports failure; failover is not a guarantee that providers will always be available.

## Activation and conversation interface

Global activation no longer serializes all covered conversations in the HTTP request: `CoverageRefreshJob` handles the refresh. The save/activation request is tracked in the lower progress monitor while agent navigation remains usable. The top Save button includes connection edits and exposes backend/hidden-field validation errors. A configured reserve can keep an agent available when its primary is unavailable.

The normal conversation list retains existing rows until replacement results arrive. Terminal batches discovered while idle do not open the monitor; followed completions auto-hide after about six seconds. Ready reviews remain actionable. Expanded batch results use native avatars. Closing/minimizing the monitor does not cancel a batch or resend a customer reply.
