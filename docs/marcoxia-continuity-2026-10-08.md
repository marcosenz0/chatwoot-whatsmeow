# MarcoXIA conversation continuity — October 8, 2026

## User-visible behavior

An individually enabled conversation keeps its AI activation while the operator analyzes history and after sending the reviewed reply. Sending a reviewed reply also enables continuation for that contact when general support is off. A model suggestion to involve the team creates an internal note without erasing explicit individual activation. Automatic general-support conversations retain their existing handoff behavior.

The analysis panel has a native slider from one public message to the complete public history. It shows the selected count and the count actually considered. The choice becomes a rolling context window for subsequent replies in that conversation. Changing the selection after analysis requires another analysis before sending, and a new incoming message or an agent edit invalidates an older draft. Analysis itself never sends a customer message.

The compact and expanded conversation rows show a robot and **IA ligada** beside the contact name when the agent is effectively active. Right-clicking one conversation offers **Gerar resposta com IA** immediately after read/unread, opening the same panel for that exact contact. Bulk menus do not offer the action. Recycling a list row, changing contacts or unmounting the row invalidates stale API responses.

**Conversa → Fuso horário do atendimento** gives an agent one timezone across its inboxes. New agents initially use the browser timezone. Existing agents may retain the inbox/reporting timezone; a saved agent timezone takes precedence. The actual current time and each public message timestamp use the selected timezone. Prompts and summaries retain dates and relative references such as yesterday/tomorrow, while avoiding unsolicited delay apologies or date announcements.

Natural splitting uses separate model reply items and the saved maximum/interval. When an enabled split produces one long paragraph, complete sentences can become separate messages; blank-line paragraphs also become separate parts. Short replies can remain one message. Links, lists, abbreviations and numbers remain intact, and excess parts are merged without losing text. Turning splitting off retains a single message.

Explicit **Desligar IA**, **Assumir atendimento**, the configured pause after a human public reply, resolved/snoozed/blocked conversations and unavailable providers continue to stop or prevent automatic work. This revision does not change the general activation switch, agent instructions, model choice, inbox ownership or provider credentials.

## Implementation and validation

- Analysis reuses the existing matching conversation state and preserves its status/manual activation; it replaces the run token to cancel old work. An approved send resumes that state with explicit individual activation. A later incoming message clears the approved-draft marker before starting its own response.
- Selected context excludes private notes and calls before taking the latest chronological public messages. Cached older memory is not reused outside a limited window. Unlimited history retains the existing incremental summary behavior.
- Analysis and autonomous responses share the timezone/current-time prompt builder. Agent timezone is validated through the existing Rails timezone registry; inbox business hours and account reporting settings are not changed.
- Delivery treats a handoff note separately from pausing explicit manual activation. Reply tokens, snapshot checks, provider availability, permissions, reply windows, media handling and queue durability remain in place.
- Native Vue components, searchable menus, existing design tokens and Brazilian Portuguese translations are reused. No UI library, custom CSS, new database table or provider bridge change was introduced.
- Conversation events carry an independent AI state timestamp. The store applies newer AI activation even when the conversation event is older, and retains it when another event carries stale AI data. The row review panel also keeps a newer fetched state. Three regression tests added during review first reproduced out-of-order state handling and then passed after the correction.
