## Architecture and runtime

New Channel::TelegramPersonal is separate from Telegram Bot API and Whatsmeow. Scoped admin-only Rails endpoints provide pairing/status/password/logout. Authenticated private callbacks process session, messages, media, edits/deletions and read receipts with namespace-scoped idempotency. Reply delivery uses stable request IDs, partial-send checkpoints and Chatwoot echo correlation.

The private Python/Telethon service uses official MTProto QR authentication, persistent per-account/inbox sessions and durable SQLite callbacks. Incoming files are queued before download, delivered to scoped Rails storage and removed after callback acknowledgment. FFmpeg normalizes recorded audio to Opus Telegram voice messages. Group/broadcast import controls are independent; bot chats are excluded. Service has one worker and runs as UID10001 with restricted persistent /data storage.

Rails web/Sidekiq: TELEGRAM_PERSONAL_SERVICE_URL and TELEGRAM_PERSONAL_SHARED_SECRET. Private service: TELEGRAM_API_ID, TELEGRAM_API_HASH, the matching per-instance shared secret, CHATWOOT_INTERNAL_URL and TELEGRAM_PERSONAL_DATA_DIR=/data. Sessions grant account access: never commit them, API hashes, QR, codes or passwords. Do not expose service ports/domains publicly. Migration: 20261005120000_create_channel_telegram_personal.rb.
