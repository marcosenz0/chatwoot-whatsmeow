# MarcoXIA editable execution instructions and presets — October 30, 2026

Marco requested direct editing of the formerly read-only Format, permissions and execution block, named presets, and restoration of the original system default. This implements that control in the Instructions tab. It does not automatically shorten or replace an existing agent prompt.

The administrator can edit platform instructions, current-request focus and memory-summary instructions. Saved custom text replaces the corresponding default. Presets are scoped to the agent and stored in its existing JSON configuration: up to 20 versions with names up to 80 characters. Selecting a version copies its text to the editor; Add/Update/Delete manage the draft versions; Save changes persists and applies the form. Deleting a version leaves its active text as Custom. Restore system default resets the three overrides to null, retaining all versions; Save applies that restoration. The original default remains generated from current agent settings. Empty custom text remains distinct from null/default.

Catalog/setting placeholders use one-pass substitution from an allowlist. A catalog containing marker-like text is data, never evaluated again. Resource/Pix catalogs retain conversation scope and do not enter the reusable cache prefix. Data remains current when catalogs change. Current-request focus is passed through automatic replies, batch plans, analysis and composer drafts; summary generation uses the configured memory text. Existing JSON schemas, actual permission checks, delivery validation, pause state and reviewed audio contracts remain enforced by the application.

The native prompt endpoint supports POST with the current form without persistence or activation; GET remains supported. Collection POST supplies defaults before the agent is created. Default restoration fetches patterns independently of malformed custom text. The frontend reloads defaults on agent changes and does not request administrative previews for read-only operators. The existing effective-prompt view now previews the current editor.

No schema migration is required. Existing profiles with no overrides retain their previous behavior. A read-only candidate runner compared HOT1's original prompt byte-for-byte before/after the implementation and confirmed the profile unchanged with zero provider calls. Current default template has 8299 Ruby characters before runtime catalogs, plus 593 focus and 411 summary instructions; browser UTF16 character counts may differ for emoji.
