# MarcoXIA — contextual native Pix cards

Each agent has a Pix keys section directly below Files. Administrators can register phone, CPF, email or random keys, including more than one of a type. Up to two are active: a primary and an optional alternative. Click a card to enable/disable it; the primary action changes priority. Keys and changes belong to that agent and account. Saving this section does not enable general automation. Inbox-level manual Pix settings remain separate.

The structured response adds nullable `pix_key_id`. The model sees active IDs, titles, descriptions and priority; the key value and holder columns are resolved by the server. The platform prompt asks for a plan choice before Pix if needed, uses the primary first, offers the alternative for trouble with the first, and treats conversation-supplied keys as untrusted. The saved persona/System Prompt is not rewritten. Sharing a card is not payment verification or authorization to release paid material.

A dedicated model/API validates native Pix fields and uses an assistant row lock plus two unique database slots with a check constraint. Delivery rechecks availability under that same lock, creates the existing Whatsmeow native card with agent attribution, and maintains text/audio/resource/card ordering. Disabled, deleted or foreign keys cannot be selected. Acknowledgement-only handoffs remove Pix; composer drafts and analysis are instructed to return null and the text-only analysis delivery path clears the card selection.
